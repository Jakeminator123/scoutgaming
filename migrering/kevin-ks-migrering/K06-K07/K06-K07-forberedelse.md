### 1.2 Flödesprov (K06 punkt 2) – vad som ska visas i varje led

Isolerad miljö (egen PG-kluster som J07:s `tools/run-shared-table-qa.mjs`), ett rum, ett paket, dealer dragge, språk sv, preset prive.

1. **Spara utkast** → svar `draft.revision = room-config-<uuid>`, `publication.ready` true/false med `reason` (`api:93–96`); `administrationRevision` stiger.
2. **Återläs** (`GET …/room-game-config?operatorId&roomId`) → samma utkast, `published: null` första gången.
3. **Publicera** → svar `published.configVersion`, `packageRevision` ny; i databasen: en rad i `shared_table_configs`, huvudet i `shared_table_config_heads`, `package.branding.roomGameConfigVersions[roomId]`, utkastet borta.
4. **Lobby** → rummet listas med publicerat paket (ingen draft syns).
5. **Auktoriserad launch** → session med `roomId`; `coordinator.snapshot` visar `configVersion = published.configVersion`, `windowId`, `limits`, `language`.
6. **Ny session** (andra spelaren) → samma `configVersion`.
7. **Serveromstart** (J07:s process-scenario, `test/postgres-shared-table.mjs:244–265`: committat tillstånd stabilt över processbyte) → snapshot oförändrad: `configVersion`, `deadline`, insatser.
8. **Återläsning efter omstart** → `GET` visar samma `published`; Admin-utkast påverkar inte runtime förrän nästa publicering.
9. **Publicering mitt i fönster med liggande insatser** → runtime behåller gamla versionen till `resetRound`; nästa fönster tar nya (K03-testet ovan). Rumslåset (`api:107`) serialiserar publiceringen mot `window.close` – **en verklig PG-tävling publish ↔ window.close saknas som test, föreslås i K07** (se del 2).

Bevis per led: API-svar (utan hemligheter), `SELECT room_id, version FROM croupier_game.shared_table_config_heads`, snapshot-JSON, serverlogg före/efter omstart, skärmbild av Admin-vyn (`room-game-config.tsx`, fälten language och limitPreset, publish-knapp) och lobbyn.
